# Marco Movie 体验评估与优化记录

日期：2026-10-29。对应版本：0.4.5 Preview。作者与维护者：Pilipala。

## 结论

搜索卡顿包含两个不同问题：界面操作是否跟手，以及外部来源多久返回。此次修复了界面线程等待拼音索引、结果反复重建、重复加载和续播直接跳入全屏等可由应用控制的问题。来源响应时间、扩展内部阻塞和网络状况仍会影响出结果速度。

评估依据为本地源码检查及目标电视上的合成场景。检查涉及首页焦点与滚动、搜索、详情与续播、海报队列、冷启动和播放器交互代码；本轮实测重点为搜索、首页和续播，没有对所有页面、网盘服务、真实来源和解码格式作完整性能验收。

## 本轮已完成

| 问题与代码证据 | 调整 | 对体验的作用 |
| --- | --- | --- |
| 搜索提交直接调用同步的拼音展开；标题学习也在界面回调里执行，与后台匹配共享索引锁 | 拼音展开、标题学习、写入学习记录转到专用后台队列，标题记录合并更新 | 输入和遥控器反馈不再等待拼音锁 |
| 每个来源返回都会移除并重建筛选与结果布局 | 结果合并刷新，筛选只追加新来源，已有卡片保持原对象与焦点 | 减少布局计算和焦点跳动 |
| 一次创建最多 120 张结果卡片及海报任务 | 首批 24 条，每个界面批次最多创建 4 张；显示更多后再补充 24 条 | 控制单次绘制工作与图片请求数量 |
| 改一个字立即清空已有结果 | 保留旧结果直到下一次搜索开始；继续保留约 650 ms 停顿触发和旧结果隔离 | 减少空白闪烁，避免过期结果覆盖新词 |
| 进入详情再返回时重新发起全局搜索 | 同一搜索页五分钟内恢复已取得的结果、筛选、焦点和列表位置；可主动刷新 | 减少重复等待。恢复内容也可能是上次搜索的部分结果 |
| 大量来源一次提交到有限队列，可能直接产生 BUSY | 按并发窗口逐个补充任务，保留失败、超时、未完成的区别 | 正常响应的百来源场景不再因批量提交溢出而漏项 |
| 已移除的搜索卡片仍可能排队下载海报 | 卡片失效时取消标记，待执行任务先检查标记；图片任务在视图挂载后提交 | 新关键词减少等待旧卡片队列 |
| 首页和历史入口直接解析并播放 | 入口先打开介绍选集页并展示保存的线路、集数与进度；详情页手动确认后续播 | 用户先确认内容，减少误播放；复用已加载的详情，避免二次详情请求 |

搜索范围仍为全部可用且支持搜索的导入配置项；“全部”视图最多展示前 120 条，可按来源筛选。增量展示不会把搜索范围缩为当前来源。

## 验证与数据边界

- 29 项电视搜索体验与历史续播检查：40 个合成来源参与、首批和加载更多、迟到来源筛选、焦点保持、返回复用、输入取消与过期响应隔离、先详情后手动全屏，以及原线路、集数和 5 秒进度恢复。
- 在索引锁被测试线程占用 400 ms 的条件下，输入和提交在界面线程上耗时 11 ms。连续 30 次合成改字操作 P95 为 3 ms、最大 3 ms。
- 上述输入数据是测试中代码操作的耗时，不是遥控器按下到屏幕显示的总延迟，也不是网络搜索时间；没有据此声称帧率提升百分比或所有设备同样流畅。
- 拼音候选输入 30 次处理的 P95 为 10 ms、最大 12 ms。
- 18 项焦点动效检查覆盖中间颜色、缩放、快速中断、轻压恢复、减少动态效果、页面移除时释放动画、弹窗与 Dock 标签焦点。
- 73 项首页检查覆盖默认推荐、历史卡片、深层向上返回、Logo 可见性、分类与焦点恢复、二级页面导航等。
- 61 项播放器与弹窗交互回归检查覆盖暂停/继续、信息收起、小屏返回、选集、字幕/倍速入口、收藏、账号面板和设置表单。
- 22 项离线搜索与输入检查，包括 100 个正常响应来源的调度、超时与空结果区分、取消任务不能交付旧结果、拼音输入与候选等。
- 实机测试使用独立偏好文件和合成内容，保留用户观看记录、账号及配置；音量为 0，结束后保持开机。

## 后续优化优先级

| 优先级 | 事项 | 方案与取舍 |
| --- | --- | --- |
| 已完成 | 全局焦点动效不一致 | 统一焦点组件已覆盖主页、分类、键盘、设置、Dock 和弹窗按钮，获取/失去焦点、按下/松开采用可中断过渡，参数见下节。 |
| 高 | 慢来源取消后仍占工作线程 | 应用能丢弃迟到结果，但扩展不一定响应线程中断。下一步为可控网络调用增加主动断开，必要时把不可中断扩展隔离到服务进程。隔离能增强恢复能力，但会增加开发和内存成本；不可用强行终止线程代替 |
| 中 | 海报重复请求与按原图大尺寸解码 | 增加同地址请求合并、按显示尺寸分级缓存及可视区加载。当前已有内存缓存和尺寸上限，本轮仅清理失效查询任务；未完成全局图片加载器改造 |
| 已完成 | 首页加载更多重建既有网格 | 0.4.8 保留既有卡片，每批最多 4 张追加；填充上一行占位后继续新行，切换分类会取消旧批次。 |
| 中 | 冷启动同步读取配置 | 将配置文件读取与解析移到后台，首页先显示可操作的加载状态；避免关闭开屏动画后暴露较长的启动等待 |
| 中 | 长时间使用的内存与播放稳定性 | 用长列表、反复进入详情、连续播放和网盘切换做持续测试，记录实际帧时间、内存与失败率。低分辨率短样本不代表高分辨率或长时间播放稳定 |
| 较低 | 背景、模糊和解码负载自适应 | 低性能设备降低柔化背景更新频率；保留减少动态效果。播放优先使用适用的硬件解码，软件解码作为兼容补充；不能通过统一强制软件解码解决所有卡顿 |

## 本轮落地的统一焦点动效

0.4.5 使用共用 FocusMotion 组件，不依赖新增动画库，也不在焦点每一帧执行海报模糊或网络请求。

- 海报和历史卡片：约 160 ms 轻微放大至 1.035，失焦约 140 ms 缩回，描边渐显；保证卡片父容器留出描边与缩放空间。
- 分类、键盘、工具栏和弹窗按钮：约 160 ms 聚焦、140 ms 失焦的亮度、描边与细微缩放反馈，避免改变布局尺寸；文字在过渡中保持清晰对比度。
- 侧边 Dock：图标约 160 ms 轻微放大；名称气泡淡入并平移约 4dp，避免长距离飞入。
- 点击：短暂轻压再恢复，与单纯聚焦有区别；不排队播放回弹，不让长按确认重复打开页面。
- 快速移动：从当前动画状态切换到新目标，取消旧动画；不用大幅弹簧、不在每帧重新模糊海报。“减少动态效果”仍使状态直接切换。

## 涉及的代码

主要改动位于 GlobalSearchScreen、SearchCoordinator、MainActivity；测试位于 ExperienceProbe、HomeProbe 与 GlobalSearchChecks。外部来源接口、账号、内容与配置不包含在本报告和公开项目中。


## 0.4.7 搜索来源与开屏

来源筛选与影视标题分层：34dp 高圆角胶囊、深蓝灰底，已选来源蓝灰高亮与加粗，聚焦白底深色字、描边和 1.035 倍缩放；确认后才切换筛选。上方 46dp 容器留出动效空间，取消旧按钮的上下外边距挤压。18 项开屏检查与 38 项搜索体验检查通过。开屏保留原始高清 Logo，文字直接在当前界面尺寸绘制；约 2.8 秒主体与 240ms 淡出，不新增视频解码器。离屏 4K 静态渲染仅检查缩放后的布局与细节。


## 0.4.8 裁切与绘制开销

首页继续播放的纵向容器、历史列表行仍保留默认子视图裁切，缩放后边框超出布局边界被截断。解除对应容器裁切，历史行另留垂直空间；不靠缩小焦点效果掩盖问题。

原柔光在每次绘制时创建 3 个全屏渐变，连续移动时与滚动、卡片过渡争用渲染时间。现用 240×135 小色场缓存，只有聚焦目标颜色改变时生成；过渡仅叠合最多两张纹理，无空闲动画。焦点取消动态阴影，跳过未改变的 drawable、文字与属性写入。原生 ScrollView 在短间隔滚动时可能直接跳转；首页使用可中断和重定向的滚动动画。整段长列表透明度改为短距离位移，避免进入页面时的离屏合成。

PerformanceProbe 在同一 1920×1080 Android 9 电视、同一预热合成海报场景下，以 Window FrameMetrics 的 TOTAL_DURATION 采集：

| 场景 | 0.4.7 P95 / 最大值 (ms) | 0.4.8 P95 / 最大值 (ms) |
| --- | --- | --- |
| 连续切换焦点 | 107.13 / 120.55 | 12.55 / 17.15 |
| 上下滚动 | 114.89 / 117.07 | 11.67 / 14.13 |
| 分页追加 | 115.26 / 165.80 | 17.41 / 22.61 |

优化后样本分别有 467、169、38 帧；超过 16.7ms 的帧分别为 1、0、4，超过 33.3ms 均为 0。基线样本分别为 266、84、26 帧。该数据是这些动画期间回调记录的帧耗时，测量分布随调度和动画数量变化；不是整机持续帧率、网络加载时间、解码表现或跨设备承诺。样本缓存已经预热，不代表网络海报首次解码表现。单条历史的两处裁切、连续滚动重定向、减少动态效果与分页保留旧卡片均做了独立检查。
